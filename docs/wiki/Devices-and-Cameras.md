# Devices and Cameras

A **device** is a milling machine. The list of devices is kept between runs and is the same for every project. The start screen selects the device; **New** and **Open…** then use it. The Device tab of the editor shows the device in use and opens its settings.

![Add a device](https://raw.githubusercontent.com/michalsarna/MillCreator/main/docs/screenshots/02-add-device.png)

## Buttons on the start screen
**Add device…**, **Edit…**, **Duplicate** and **Import…** (strictly checked: a newer format, a wrong number or a file over 2 MB is refused) in the first row and **I have no device** in the second. **Export…** (one device as a JSON file) and **Delete** (asks to confirm) are in the window of **Edit…**. A copy or an imported device with a name that is taken gets a number: `Router (2)`.

## I have no device
Makes, once, a plain device called **Dummy**: a 300 × 200 mm work area with 60 mm of travel in Z, safe height 5 mm, spindle 1000–24000 rpm. It stays in the list like any other device and can be edited; the project is saved with it as its machine. **New** and **Open…** without any device make and use it too.

## Device settings
**Machine → Device settings…** (or **Edit…** on the start screen) opens the settings of the device, in twelve pages:

| Page | What it holds |
|---|---|
| General | name, controller, units (mm or inch; geometry is always stored in mm), **Machine zero (0,0)** (front left, front right, back left, back right), **Work coordinates** (None, or G54 … G59) and the **Zero of the program**; for a new device **Start from** (a usual machine size) |
| Machine | work area X, Y and Z, **Safe height** (where the spindle moves between cuts), **Speed of moves above the material**; the values read from the controller and the copies of its settings |
| Spindle | **Lowest speed**, **Highest speed**, **Wait after switching on**, **Tool changer** |
| G-code | the device's **own G-code** (eight boxes, see below), the variables and the **Own file format** |
| Connection | serial port or network socket, port or USB id, baud rate, the GRBL version, streaming, what to do after connecting; or a Duet board over HTTP |
| Camera | up to eight cameras (see below) |
| Rotary | a rotary attachment: kind, diameters, microsteps per turn |
| Jogging | the steps of X and Y and of Z for the jog buttons, the jog speeds, **Check the program before every run** |
| Probe | a touch plate (its thickness and the thickness of its side) or a 3D touch probe (the offset of Z, the diameter of the ball), the fail distance, the retract and the speeds |
| Macros | buttons of your own G-code, and G-code before and after every job |
| Maintenance | reminders: what to do and every how many hours, **Done** when it was done |
| Notes | free text about the machine |

The controller is GRBL (0.7 to 1.1 and newer), or **Smoothieware** (a choice of the *GRBL version* list), or a **Duet / RepRapFirmware** board over HTTP (a check box on the Connection page with the address and a password that is not saved; see Machine Control). The **Spindle** page also has **Tool changer** (`T<n> M6`), and the **G-code** page the lines for the dust collector. The **Connection** page sets how to reach it (a serial port or a network socket, baud rate, counting or simple streaming, homing or clearing an alarm after connecting) and the **Rotary** page a rotary attachment (chuck or rollers, workpiece diameter, microsteps per turn; the Y axis turns the work). The **Device** tab of the editor has Connect, Home, Unlock, Pause, Resume, the state and position of the machine and a console.

## Camera
The **Camera** page of the device settings holds up to eight cameras (**Add a camera**): for each a **Camera name**, **Switched on**, an **Address** (MJPEG stream, JPEG snapshot, http / https, or an rtsp, udp, rtp or rtmp stream) or a **Camera of this computer** with its **Camera number**, and the **Camera rotation** (0 / 90 / 180 / 270°); one of them is the camera shown. When the device has a camera that is switched on (and valid), the editor gets a **Camera** tab in the side panel and the **Camera view** button above the work area, which opens the picture as a tab of the work area (it can be dragged to another pane or opened in a separate window, like the preview). Pictures from an address use the stream reader of baseCreator; cameras of the computer need a build with `--features camera`. Rotation and the picture adjustments of the camera are applied.

## In the project
The project keeps a snapshot of the device it was made for (name and the three sizes of the work area). When it is opened for a device whose work area differs, the status bar says so.

**Own G-code (page G-code).** Eight boxes, one command per line (at most 20 lines of 100 characters; control characters are refused): **Very start of the file** (before the comments and the header), **At the start of the program** (after the header and the work coordinate word), **At every change of the bit** (also when the first bit is taken; after the pause for the change and before the spindle starts, for example `T1 M6` or a coolant command), **At every change of the operation** (a new layer; after its comment, before the bit is looked at), **At the end of the program** (after the head is back at the zero, before `M30`), **Very end of the file** (after `M30`), and **Dust collector on** / **Dust collector off** (used by the layers that ask for the dust collector). The lines go into every G-code the program makes: the file, the G-code text tab, the job that is sent, the dry run. They are the machine's own commands, so the program does not check them: try a new line without a bit in the machine first.

**Variables, the very start and end of the file, and the file format (page G-code).** In every box of own G-code a word in braces is replaced when the file is made: `{project_name}`, `{project_path}` (empty while the project has not been saved), `{date}` and `{time}` (UTC), `{machine_name}`, the box of everything that is cut in the coordinates of the machine (`{min_x}` `{max_x}` `{min_y}` `{max_y}` `{min_z}` `{max_z}`) and its size (`{width}` `{height}` `{depth}`); in the change of the bit and of the operation also `{layer_name}`, `{layer_index}`, `{total_layers}` and the ones of the bit of the layer: `{tool_number}` (its place in the changer, 0 if it has none), `{tool_name}`, `{tool_diameter}`, `{tool_flutes}`, and the speeds of the bit in the library `{tool_rpm}`, `{tool_feed}` and `{tool_plunge}`. The list is under the boxes; an unknown name is shown in red and no file is made until it is mended. *Very start of the file* is written before the comments and the header (for a `%`, a program number or the header of a controller) and *Very end of the file* after `M30`. **Own file format** is the last pass over the finished program, for controllers that read G-code in their own way; everything is off by default and then the file is the same as before: *Decimal point after whole numbers* (`X1` becomes `X1.`, for X, Y, Z, F, P, I, J, K), *% at the start and end*, *Dwell word* (`G4 P` in seconds, `G4 P` in milliseconds or `G4 X` in seconds; the value is converted), *Line numbers* (N10, N20, … with a step) and *Remove comments*. With the same thing switched on in a postprocessor of the plugin *G-code tools* the status line warns that it is done twice.

**Work coordinates (G54 … G59) and the zero of the program (page General).** By default the program counts from the machine zero (the corner chosen as *Machine zero*), as before. When you choose **G54 … G59**, the program starts with that word (so the machine uses the work coordinate system whose zero you set on it, for example by touching the material) and every X and Y is counted from the **zero of the program**: a point of the work area given as X, Y (the work area is counted from the corner of the machine zero). With zero 0, 0 the numbers are the same as without a code, only the word is added. The frame (*Frame*), the dry run and the job all use it, and so do the return to the zero at the end and the own G-code. Z is not changed: it is counted from the top of the material.

**The zero of the program on the work area.** In the device settings, next to *Zero of the program* (X, Y) the button **Pick on the work area** lets the next click on the work area set the zero; it snaps to the corners and the middles of the shapes and to the corners of the work area (Esc cancels). While a work coordinate system (G54 … G59) is chosen, an **icon of the axes** (X red, Y green, with the name of the system) stands at the zero on the work area; drag it and the fields of the settings follow at once. One pick or one drag is one step of *Undo* (Ctrl+Z), as long as nothing else was changed after it. The zero is saved with the device when the settings are saved.

## Camera: RTSP, photos, video and time-lapse

* **RTSP streams** (`rtsp://` or `rtsps://`, with the user and password in the address when the camera asks for them) work as an address of a camera. The stream is decoded by **ffmpeg**, which is run as a separate program: it is looked for next to the program (the packages bring one), in the resources of a macOS app and then in the PATH of the system. Without it the camera view says so. If the stream breaks it is opened again every few seconds. The address with a password can be seen in the list of processes of the computer: use a camera account that can only look.
* **Other streams:** `udp://` and `rtp://` (MPEG-TS or RTP from an encoder, also multicast; `udp://@:5000` listens on a port) and `rtmp://` are read by ffmpeg the same way. A stream that gives nothing for 20 seconds is taken for dead and opened again. TLS addresses (`rtsps://`, `rtmps://`) are not supported by the small ffmpeg of the packages.
* **Camera options** (under the address of a stream that ffmpeg reads, off by default): **Use UDP for RTSP** (only for an `rtsp://` address; less delay than TCP, but the picture can break on a bad network; off: TCP) and **Low latency** (the newest picture sooner, without buffering; the picture can stutter). The stream is opened again when they change.
* **Video format** (in the camera view): **Automatic** (the default) copies the stream of an IP camera (rtsp, udp, rtp, rtmp) into an **MP4** file as it comes. Nothing is decoded or encoded again, so the processor has next to nothing to do and the quality is the one of the camera. The copy is the stream as the camera sends it: the rotation and the picture settings of the program are not applied to it. A camera that gives one picture after another (an MJPEG address, a camera of the computer) is recorded as **AVI** (Motion-JPEG). **MP4** asks for the copy (a camera that is not a stream is recorded as AVI, and the line under the buttons says so); **AVI** always writes Motion-JPEG pictures. The copy needs ffmpeg; without it the video is AVI.
* Under the picture of the camera view: **Take a photo** (a JPEG), **Record video** / **Stop recording** (the line beside it counts the seconds, and the pictures of an AVI) and the **Time-lapse**: **Every** N seconds, or **After each layer** (a picture when the next layer of the job begins and when the job ends; it needs a job sent to the machine from the program with **Start**), then **Start time-lapse** / **Stop time-lapse**. A recording goes on while the camera view is closed or hidden.
* **Where the files go.** Without a folder chosen, they go to a folder **`camera` next to the project file**; when that folder is there already, to the first free one of `camera00`, `camera01`, … (and the same folder for the rest of the run). A project that has not been saved yet uses the folder `camera` of the shared data folder. The line **Folder** shows where the next file goes, and **Choose the folder…** sets one folder for everything (kept for all the programs, with the video format and the time-lapse settings, in `camera_recording.json` in the shared data folder).
* **The names of the files** start with the name of the project file and are numbered: `box-photo-0001.jpg`, `box-video-0001.mp4` (or `.avi`); a time-lapse gets a folder of its own (`box-timelapse-0001`) with `box-frame-00001.jpg` (every N seconds) or `box-layer-00001.jpg` (after each layer). Without a project file the names have no prefix (`photo-0001.jpg`).
